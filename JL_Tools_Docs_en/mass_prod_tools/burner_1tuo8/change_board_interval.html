2.8. Board-Change Interval Setting

2.8.1. Use case

In mass production, a fixture is generally used so that N programmers program N*8 devices at the same time. While dozens of devices are being programmed simultaneously,
contact problems may occur when the fixture is pressed down, some chip performance tests may be rather strict, or the chips themselves may have problems, causing programming errors on individual devices.
When this happens, you may want to program only the failed devices again and avoid programming the successfully programmed devices a second time, both to avoid problems caused by repeated programming and because repeated programming may also waste the fw file's programming count, authentication codes, Bluetooth addresses and so on.

This requirement can be met by setting a board-change interval.
With the board-change interval set to 1000mS, the programmer measures the time from when a successfully programmed device on the current channel goes offline (the device is removed) until programming starts again:
if the interval is longer than 1000mS, all channels are allowed to program;
if the interval is shorter than 1000mS, only the channels that failed are allowed to program again.

2.8.2. Setting the board-change interval

Following the relevant steps in the section "Update the target chip firmware on the programmer", open the control panel for updating the AC897N chip firmware in version V3.0.32. The board-change interval (换板时间) option is at the top of the panel. The default board-change interval is 1000mS, and you can change it as needed (do not set the board-change interval too long, otherwise mass-production programming efficiency will drop), as shown in Board-change interval setting screen.

2.8.3. Usage

  1. To reprogram only the devices on the channels that failed this time, reprogram within the board-change interval, counted from when the current board's devices go offline (are removed). The devices that failed last time are programmed through the normal procedure, while the progress bars of the channels whose devices were programmed successfully change as shown in Progress bar of a successfully programmed channel within the board-change interval.

  2. If, counting from when the current board's devices go offline (are removed), devices are inserted again after the board-change interval has elapsed, the devices' chips on all channels are programmed, regardless of whether the previous programming succeeded or failed.
