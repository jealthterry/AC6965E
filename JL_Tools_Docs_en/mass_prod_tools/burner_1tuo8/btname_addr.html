2.12. Bluetooth Address and Name Auto-Increment

Important

The Bluetooth address programmed by the programmer is the EDR address (not the BLE address; see Notes)

2.12.1. Use case

For a batch of Bluetooth products based on the same chip, the goal is for the Bluetooth address of every chip to fall within a specified address range, with each chip having a unique Bluetooth address. To achieve this, when updating the fw programming firmware, configure the corresponding Bluetooth address range in the programming options of the PC tool; while the target chip firmware is being programmed, the Bluetooth addresses are programmed into a specified location in each chip in incrementing order, so that the Bluetooth address programmed into the chip can be used in SDK development. In addition, in SDK development, the Bluetooth address can be appended to the Bluetooth name in a specified format, making the Bluetooth name unique.

2.12.2. Bluetooth address auto-increment configuration

In the control panel for updating the target chip firmware, after opening and selecting the target chip fw file to be programmed, proceed as shown in Bluetooth address auto-increment configuration:

  • [1] Check "Update Bluetooth address" (更新蓝牙地址) (if unchecked, the SDK uses a randomly assigned Bluetooth address);

  • [2] Enter the Bluetooth address auto-increment range;

  • [3] Choose whether to check "Overwrite Bluetooth address" (覆盖蓝牙地址) (if checked, a chip that already has a Bluetooth address is overwritten with a new address; to avoid waste, it is generally left unchecked);

  • [4] Click Deploy (部署) to update the fw file and configuration information to the programmer;

Important

The address range set each time must not exceed the u32 range. Otherwise, the error [Bluetooth address initialization failed] (蓝牙地址初始化失败) may be reported

2.12.3. Programming Bluetooth addresses into the target chip

  1. Bluetooth addresses are programmed in incrementing order, starting from the lowest address in the address range configured in the programming options. While programming the chip firmware, the programmer also programs the Bluetooth address into the target chip.

  2. For example, if the Bluetooth address range is set to 00: 00 : 00 :00 : 00 : 01 - 00: 00 : 00 :FF : FF : FF, the Bluetooth address of the first chip after successful programming is 00: 00 : 00 :00 : 00 :01, that of the second chip is 00: 00 : 00 :00 : 00 :02, and so on. After all addresses in the set range have been programmed, the programmer reports "Bluetooth addresses used up" (蓝牙地址已用完) and can no longer program firmware. Bluetooth addresses are unique: each chip is programmed with a different Bluetooth address.

  3. With the Bluetooth address auto-increment function enabled, the progress bar section of the programmer display's normal screen shows the available Bluetooth address that the programmer has assigned to the current channel, as shown in Bluetooth address display screen. When a device on the current channel is programmed, the current Bluetooth address is programmed into the target chip; after successful programming, the programmer assigns a new address to the current channel.

2.12.3.1.1. Common issues

  1. How to keep the original address when reprogramming chips that already contain an address:

    • Check [Update Bluetooth address] (更新蓝牙地址), uncheck [Overwrite Bluetooth address] (覆盖蓝牙地址), and set the address range to the original range of the chips

    • Reprogram these chips that already have addresses

    • Note that at this point you must not mix in chips without an address; otherwise, some devices will end up with duplicate addresses

2.12.4. Implementing Bluetooth name auto-increment

  1. How it works

    When the Bluetooth address auto-increment programming feature is configured, each chip is programmed with a Bluetooth address within the specified range. In the SDK, the Bluetooth address can be read through the corresponding function interface and appended to the Bluetooth name in a specified format, so that the Bluetooth name auto-increments with the Bluetooth address and each Bluetooth name is unique (if you are not sure how to implement this in the SDK code, consult Jieli technical support).

  2. Bluetooth name auto-increment example

    • For example, if the Bluetooth address auto-increment range configured when updating the programming file is 00: 00 : 00 :00 : 00 :01 - 00: 00 : 00 : FF : FF :FF, the Bluetooth address of the 1st chip programmed successfully is 00: 00 : 00 :00 : 00 :01, that of the 2nd chip is 00: 00 : 00 :00 : 00 :02, and so on;

    • For example, if the Bluetooth name prefix set in the SDK is AC897N_Main and the Bluetooth name format is Bluetooth name prefix + last 8 digits of the address; after this is implemented in the SDK code, the Bluetooth name for Bluetooth address 00: 00 : 00 :00 : 00 :01 is AC897N_Main_00000001, the Bluetooth name for Bluetooth address 00: 00 : 00 :00 :00 :02 is AC897N_Main_00000002, and so on. You can define other Bluetooth name formats and implement them in the SDK code to auto-increment the Bluetooth name according to the Bluetooth address.

2.12.5. Viewing the next Bluetooth address to be programmed

With Bluetooth address auto-increment checked, if you want to view the next Bluetooth address to be programmed without inserting a device for programming, look at the Current address (当前地址) shown on the programmer's scrolling information screen. This is a Bluetooth address that has not been programmed yet; when a device is inserted for programming, this Bluetooth address is the one programmed. This Bluetooth address is displayed so that you can easily see the remaining Bluetooth address range. The Current address display is shown in Current Bluetooth address display screen.

2.12.6. Notes

  1. If other target chip firmware is updated before the Bluetooth address range set in the PC-side programming options has been used up, the remaining Bluetooth addresses become invalid. Plan their use carefully to avoid unnecessary waste.

  2. The Bluetooth address programmed by the programmer is the EDR address. In some SDKs, the BLE address is calculated from the EDR address (for the calculation method, ask the person who provided the SDK) and is not programmed by the programmer (the BLE and EDR addresses are usually different).

2.12.7. Keeping the chip's existing Bluetooth address when reprogramming

In some scenarios, chips that have already been programmed with a Bluetooth address need to keep their existing Bluetooth address when they are reprogrammed with new firmware. There are usually the following two cases.

2.12.7.1. Bluetooth address in the chip's FLASH programmed by a 1-to-2 or 1-to-8 programmer

If the Bluetooth address in the chip's FLASH was programmed from a specified range using a 1-to-2 or 1-to-8 programmer, the location of the Bluetooth address is fixed.

  1. Select [Sequential auto-increment] (顺序自增) to keep the address. With this method, if the Bluetooth address already in the chip's FLASH is within the set range, it is not erased but kept during reprogramming; if it is not within the set range, it is erased and a new address is written. Before programming, you can first spot-check some chips to see the previously programmed Bluetooth address values. Suppose the Bluetooth address of a spot-checked chip is 85:A6:33:43:87:E4 and the first two bytes of the other devices all start with 85 A6; you can then configure the Bluetooth address range as 85:A6:00:00:00:00 ~ 85:A6:FF:FF:FF:FF. As long as the Bluetooth address of the device's chip is within the set address range during reprogramming, it is not erased. The precondition is that the first two bytes of all devices must be identical, so that a range containing the devices' Bluetooth addresses can easily be set for reprogramming while keeping the existing Bluetooth addresses in the chips. This restriction exists mainly because the auto-increment counter is only 4 bytes long.

  2. Select [Retain auto-increment] (保留自增) to keep the address. With this method, the address in the FLASH is not erased during reprogramming, regardless of whether the Bluetooth address already in the chip's FLASH is within the set auto-increment range; if the chip's FLASH contains no address, an address from the set range is programmed into the chip.

2.12.7.2. Random address generated automatically by the SDK

Depending on the chip model, the Bluetooth address generated automatically by the application may be stored in the VM area or in the bt_info area. To keep the existing Bluetooth address in the chip's FLASH during reprogramming, you cannot use the sequential auto-increment or retain auto-increment methods described above; instead, uncheck the [Erase entire FLASH before programming] (烧写前擦除整个FLASH) and [Erase VM] (擦除VM) options, and also make sure that the FW to be reprogrammed has the same VM address as the firmware already programmed into the chip (if the Bluetooth address is stored in bt_info, also make sure that this configured address is the same). After reprogramming, whether the address has been kept must be confirmed by actual testing.
