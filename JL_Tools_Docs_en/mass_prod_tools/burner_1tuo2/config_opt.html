1.5. PC-Side Programming Options for Each Chip Model

Note

If you want these checkbox options to be fixed in the FW/UFW file so that you do not have to select them again for every deployment, see How to Set Programming Options When Generating a Programming File

1.5.1. Opening and selecting configuration items

When you update the fw programming file, the update window of the PC tool has a "Configure" (配置) control. Click "Configure" (配置) to display many optional or required configuration items. Normally the defaults are fine, but you can also select them according to customer requirements.

For example, if you open the configuration window for updating AC897N chip firmware in version V2.23.7, the available configuration items are DAC, IQ_TRIM, LNA, Crystal-less solution (LRC_TRIM) (免晶振方案), Force authentication code update (强制更新认证码), PA, REF_TRIM, LVD and Bluetooth configuration (蓝牙配置), as shown in Chip programming configuration window.

After loading the target chip firmware fw file, configure each configuration item, then click "Update" (更新) to update the target chip firmware and configuration information to the programmer.

Note

The configuration window may differ between programmer firmware versions. Keep the programmer firmware updated to the latest version.

1.5.2. Common configuration items for each chip model

The programming configuration items are basically the same for different chip models: configuration items with the same name have the same function on different chips. The table below describes some common configuration items for each chip series; configure them as needed when programming.

Configuration item

Configuration Items

REF_TRIM

If checked, calibrates the chip's ADC reference source (with a reference voltage supplied externally to the chip); used to prevent chips that were not calibrated earlier from entering production

REF_IO

The drop-down options are the chip IO pins to which the 2.5V reference voltage for REF_TRIM is connected; select according to the actual hardware circuit of the programming socket;
most chips do not have this option and use the default IO, and mass-production chips are already calibrated at the CP stage, so the default configuration is fine

Crystal-less solution (LRC_TRIM) (免晶振方案)

If checked, performs LRC clock calibration on chips that do not need an external crystal, so that the chip's LRC clock source is used as the system clock

LVD voltage (LVD电压)

Sets the chip's low-voltage reset voltage. For a second programming, it must be set to the same value; otherwise, an error is reported and programming cannot continue.
Set the LVD voltage based on your actual design and the SDK documentation
This setting can be programmed only once; choose carefully

Force authentication code update (强制更新认证码)

If checked, when a non-blank chip is programmed, any authentication code data already in the chip is overwritten with a new authentication code.
It is unchecked by default: if the chip already has an authentication code, the existing one is used to avoid wasting authentication codes. See the "Programming Third-Party Data (Authentication Codes)" section;

Force multi-algorithm authorization update (多算法授权强制更新)

Checked: if authorization data has already been programmed into the chip, programming it again with this option checked
forcibly updates the chip with the authorization data currently being programmed, which deducts from the authorized count
Unchecked: if the chip already contains authorization data that matches the data currently being programmed,
the data is not programmed into the chip again and nothing is deducted from the authorized count

Bluetooth address

If checked, enter the Bluetooth address range and also check "Auto-increment" (自增);
when the chips are programmed, incrementing Bluetooth addresses are programmed into each chip.
You can also check "Random" (随机) to program random addresses into the chips. See the "Bluetooth Address and Name Auto-Increment" section;

Battery type (电池方案)

Sets the chip's LVD (low-voltage reset) voltage according to the operating voltage of the battery type used with the chip;
Options: lithium battery (3.0V~4.4V), LVD voltage 2.3V;
two dry cells (1.8V~3.2V), LVD low-voltage reset disabled;
coin cell (2.2V~3.6V), LVD voltage 1.8V;
This setting can be programmed only once: after programming with one option, you cannot program again with another option. Choose carefully

AC95N/AC96N programming options (AC95N/AC96N烧录选项)

Linear charging current level (mA) (线性充电电流档位): set the linear charging current level according to the design;
Switching charging current level (mA) (开关充电电流档位): set the linear charging current level according to the design;
VOUT(mV): the VOUT voltage to which the boost module needs to be adjusted;
VBAT(V): select 4.2V or 4.35V according to the battery type used.
Analog recalibration (模拟再校准): when enabled (select on), you can reconfigure the linear/switching charging current levels and modify the VOUT and VBAT parameters before programming again;
Power consumption test (功耗测试):
enter the power consumption test limit (uA) to test the chip's low power consumption and screen out chips whose power consumption does not meet the requirement (requires support from the programming socket hardware);
select OFF or enter 0 to turn off the power consumption test

Enable (pin) short-press reset (使能（引脚）短按复位功能)

If checked, the corresponding configuration value is programmed into the chip to enable the chip's short-press reset function.
This setting can be programmed only once; choose carefully

Enable (pin) long-press reset (使能（引脚）长按复位功能)

If checked, the corresponding configuration value is programmed into the chip to enable the chip's long-press reset function.
This setting can be programmed only once; choose carefully

Bare chip programming (裸片烧录)

If checked, programs chips that have already been mounted directly on the board in a black-epoxy (glob-top) package.
The LVD and VDDIO voltage levels of this type of chip are different.
This setting can be programmed only once; choose carefully

Blank chip programming (空片烧录)

If checked, the programmer does not check whether the flash data is all FF and does not erase the flash (before a chip leaves the factory, its flash data is all FF, so no erase is needed);
Purpose: to reduce the overall programming time and improve mass production programming efficiency (programming time depends on the flash capacity; checking this option can save more than 200mS of programming time)
If there is an "Erase entire flash" (擦除整片flash) option, "Blank chip programming" (空片烧录) only takes effect when "Erase entire flash" is also checked

Erase entire flash (擦除整个flash)

Checked: the entire flash of the chip is made all FF before the firmware data is programmed;
Unchecked: if the existing VM area data meets the retention rules, then during a second programming
the VM area data is not erased (the VM area data created after the first programming and power-on is retained)

Power consumption test (uA): xxx (功耗测试)

Select OFF: no soft power-off power consumption test is performed on the chip;
Enter a specific value, e.g. "10": a soft power-off power consumption test is performed on the chip; if the measured value is greater than 10uA, programming reports an error and the chip is treated as defective
Note:
1. The programming socket for the power consumption test does not need an LDO conversion circuit; if it has one, do not check this option;
2. Leave some margin in the limit: for example, to screen out chips above 2uA, set 5uA or more

Flash LVD voltage match (Flash Lvd电压匹配)

If checked, checks whether the selected LVD voltage matches the minimum operating voltage supported by the chip's flash;
(1) If the selected LVD voltage is greater than or equal to the minimum operating voltage supported by the flash, programming is allowed;
(2) Otherwise, programming is not allowed, and the programmer reports an error showing the minimum operating voltage of the chip's flash
(3) If this error is reported, uncheck the option and select the LVD voltage level you need; in general, programming with the highest LVD voltage level is recommended

Charging enable (充电使能)

This option controls the VBAT output during the initial power-on stage of the chip and is checked by default.
Some designs connect VBAT and VDDIO together and may therefore need to turn off the VBAT voltage output during the initial power-on stage;
in that case, you may need to uncheck this option for programming. Configure it according to the actual application

UART-controlled programming (串口控制烧录)

If checked, you can use an RS232 serial port and the "PC Bluetooth address programming tool" (PC蓝牙地址烧录工具) to control the programmer to program Bluetooth addresses,
preventing duplicate or lost Bluetooth addresses and making Bluetooth address data easier to manage

Programming voltage (烧录电压)

Select Default if the programming socket has an LDO conversion circuit, i.e. the chip is powered by converting the 6.5V on the programmer's pin header to the voltage the chip needs, such as 4.2V, for programming;
select another specific voltage (4.2V~6.8V) to have the programmer's 6.5V pin header output the configured voltage directly to the chip, which saves the LDO circuit components

XOSC_PIN_MODE

Auto (自动): the programmer automatically detects whether the chip uses single-pin or dual-pin crystal oscillator mode;
Single pin (单脚): the chip uses the single-pin crystal oscillator wiring;
Dual pin (双脚): the chip uses the dual-pin crystal oscillator wiring;
Note: the default is Auto. Normally, select single-pin or dual-pin mode only if programming in Auto mode reports an error (automatic detection fails)

PB1_PU_TRIM

If checked, calibrates the chip's PB1 pull-up resistor; used in designs where PB1 is connected to AD KEY buttons, to ensure that the AD key values do not conflict

OTP reprogramming (otp重新烧写)

If checked, chips with an OTP programming error are programmed once more

POWERON_TIME

The time for which the programmer powers the chip after resetting it once programming has succeeded, in mS; this setting is used only by AC632N
The input box defaults to 0, meaning no reset and power-on after successful programming; if you enter N (a non-zero value), the chip is reset and powered on for N mS after successful programming

Programming with crystal (带晶振烧录)

Indicates whether the programming socket hardware, i.e. the top board, has a crystal connected for programming. Checking it can solve unstable programming communication caused by the environment in crystal-less designs;
When the SDK is a crystal-less design, you must also check "LRC_TIRIM" in the configuration window for programming

Power-off duration (ms) (断电持续时间（毫秒）)

When the chip needs to be powered on after programming to run the SDK and perform Bluetooth trim (calibration),
the time entered is the power-off time after programming, i.e. how long the chip stays powered off before it is powered on again

Power-on duration (ms) (上电持续时间（毫秒）)

When the chip needs to be powered on after programming to run the SDK and perform Bluetooth trim (calibration),
the time entered is how long power is supplied to the chip after it has been powered off for a certain time following programming

Screening test items (筛选测试项)

Used to screen out chips whose parameters fail the individual test items, preventing such defective chips from entering subsequent production steps

SFC verification (SFC校验)

Select the speaker solution (音箱方案) or another solution (其他方案) according to your design. During programming, under the voltage test conditions used by the selected solution,
the firmware data is verified in SFC mode to screen out chips that fail firmware data verification

LOOP_BACK

If checked, tests Bluetooth performance parameters to screen out chips whose parameters do not meet the requirements

DAC

If checked, tests the various voltages of the DAC module to screen out chips whose DAC parameters do not meet the requirements, e.g. chips with noise

IQ_TRIM

If checked, tests Bluetooth calibration parameters to check whether the chip's transmit-to-receive path
works properly, screening out chips with abnormal transmit/receive paths

LNA

If checked, tests Bluetooth receive performance to screen out chips with damaged transistors inside the LNA;
screens out chips that show a short receive range or connection problems

PA

If checked, tests Bluetooth transmit performance to screen out chips whose Bluetooth transmit parameters do not meet the requirements

DACVDD

If checked, screens out chips with abnormal dacvdd caused by mixed materials during packaging

LNA_BIAS

If checked, tests Bluetooth calibration parameters to screen out chips whose Bluetooth parameters do not meet the requirements

USB screening mode (USB筛选模式)

Options are Normal programming (正常烧录) and Strict screening mode (严格筛选模式). For AC695X designs, select the mode according to
whether the USB pins are used, to screen out chips with faulty USB pins

DAC OS

If checked, screens out AD698N/AC638N chips with abnormal DAC diode characteristics;
see the "Other Common Features: Configuration and Use" section;

Full RAM test (RAM全面测试)

If checked, screens out chips with an abnormal RAM module, which fail to boot or boot abnormally

RAM_240M

If checked, screens out chips whose RAM module is abnormal at a 240M chip clock, which fail to boot or boot abnormally

ROM_240M

If checked, screens out chips whose ROM module is abnormal at a 240M chip clock, which fail to boot or boot abnormally

FTMAX_240M

If checked, screens out chips whose FTMAX module is abnormal at a 240M chip clock

DC TEST

If checked, tests the LDO voltage levels to screen out bad chips whose level voltages are abnormal because of overvoltage damage.
Unchecked by default; check it if problems such as VDC12 or xosc overvoltage occur.

UMDC

If checked, tests together with LOOP_BACK to screen out chips whose Bluetooth parameters do not meet the requirements

ighg

If checked, screens out chips whose Bluetooth performance parameters do not meet the requirements

fdiv

If checked, screens out chips with an abnormal floating-point divider

IO

If checked, screens out chips at risk of crossed bonding wires, i.e. chips with abnormal IO;

IO_TEST

If checked, screens out chips at risk of crossed bonding wires, i.e. chips with abnormal IO;
for some chips, the IO can be tested according to the package;
select DISABLE for no test; if your package is listed, select the corresponding package model;
if it is not listed but you need the test, select OTHERS

BTPLL

If checked, tests whether the local oscillator frequency (carrier) generated by the local oscillator is correct, screening out chips with an abnormal BTPLL

BTDC_SP

If checked, screens out chips with an abnormal Bluetooth-related BTDC_SP module

AUDIO_RAM

If checked, screens out chips with AUDIO_RAM read/write errors under different frequency and voltage conditions

BTDC_AUADC

If checked, screens out chips with low Bluetooth transmit power, i.e. chips with an abnormal AUADC module

SRC

If checked, screens out chips with an abnormal audio SRC module

LRC_DIFF

Select a percentage. During programming, the current LRC clock calibration value is compared with the previously calibrated value; if the deviation exceeds the configured percentage, the chip is treated as defective;
Note:
This test is only for cases where you do not want to update the SDK. If the SDK already has the corresponding patch and "LRC=-1;" is configured in isd_config.ini, this test is not needed

Power consumption test (功耗测试)

Select OFF for no power consumption test; enter a non-zero value to perform a soft power-off power consumption test on the chip during programming;
for example, if you enter 10 and the measured power consumption of the chip is greater than 10uA, programming reports an error and the chip is treated as bad;
Note: the power consumption test requires support from the programmer hardware, i.e. the top board (chip programming socket); the top board does not need an LDO conversion circuit

Use pdown scheme (使用pdown方案)

Select Yes (是) if the design uses the low-power wake-up function;
during programming, the RAM is then tested under the various conditions of the pdown scheme, so that abnormal chips are screened out in advance
