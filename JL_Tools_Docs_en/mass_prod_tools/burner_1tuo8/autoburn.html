2.3. Automated Programming with a Handler

2.3.1. Introduction to automated programming

  1. Purpose

    Manual programming is slow. Automated programming with a handler greatly increases programming speed and solves the problem of low manual programming efficiency.

  2. How it works

    The handler controls automatic programming mainly through IO signals on the programmer, taking over the work of two manual programming steps: "start programming" and "judge the programming result". A robot arm places the board in the fixture and starts programming; the handler monitors the programming status indicated by the IO signals in real time, then judges and handles the programming result.

The V2.0 programmer provides an interface for wiring the automatic programming IO signals. For automatic programming with the V1.2 programmer, some hardware must be modified to bring out an IO signal interface, and support in the programmer firmware is required.

2.3.2. IO control signals for automated programming

  1. Automatic programming IO interface

    The automatic programming IO interface actually consists of the IO pins that turn the red and green programming status LEDs of each channel on and off. The automatic programming IO interface of the V2.0 programmer is shown in Automatic programming IO interface.

  2. IO control signals

    The IO control signals of all 8 programming channels map to programming states in the same way. Different IO signal level combinations (red and green LEDs on or off) correspond to different programming states, as shown in the following table (provisional; you can contact Jieli technical support).

    Programming status

    Red LED

    Green LED

    Initial state

    Low (red light off)

    Low (green light off)

    Programming in progress

    High (red light on)

    High (green light on)

    Programming succeeded

    Low (red light off)

    High (green light on)

    Programming failed

    High (red light on)

    Low (green light off)

2.3.3. Program the device chips automatically

2.3.3.1. Preparing for automated programming

  1. Before programming the device chip firmware automatically, make sure you have carried out the related operations in the relevant subsections of "Manual Programming, Verification and Blank Check" to avoid problems during programming. These operations include:

    • Power on the programmer before programming and wait for the ready-to-program screen (see the "Power on the programmer" subsection)

    • Confirm that the programmer firmware is the required version, or update it (see the "Checking and updating the programmer firmware version" section; check this from time to time)

    • Confirm that the target chip firmware currently in the programmer is the firmware to be programmed, or update it (see the "Update the target chip firmware on the programmer" subsection)

    • Confirm that the programmer's working mode is Programming mode, or set it (see the "Programmer working modes: introduction and setup" section)

  2. Set up the programming environment of the automated programming handler.

2.3.3.2. Automated programming flow

When the preparations for automatic programming are complete, power-cycle the programmer and turn on the USB power toggle switch so that the programmer display is in the ready-to-program state. When the programmer detects that a USB male connector wired to the VBAT, DM, DP and GND pins of a device chip has been plugged into a USB programming port, it starts programming the device chip on that channel.
