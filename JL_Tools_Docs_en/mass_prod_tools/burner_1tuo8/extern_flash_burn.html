2.18. Upgrading Internal and External Flash Together

Support for upgrading the internal flash and the external flash at the same time was added in programmer version V3.1.8. To use this feature, you need to modify file parameters in the SDK's download directory.

2.18.1. Resource packing program

Download the archive Download directory tools for Windows (click here to download) and extract it
to get the latest version of packres.exe, then put it in the SDK's download directory

2.18.2. Adding build parameters

  1. Find the download.c file in the download directory and add a command, for example:

    packres.exe -n test_dir -o res.bin  dir_tone 0 -normal

    Note

    Parameters:

    • -n test_dir # the name used when the chip accesses it, e.g. test_dir

    • -o res.bin # output file name: res.bin

    • -normal # removes the index

    • dir_tone 0  ... # file name and address (the address in the external flash to write to; the 1-to-8 programmer needs to parse it)

    Important

    Note: the packres.exe tool is used in several places. For example, packing prompt tones also uses packres.exe, and so does packing files for download to the external flash. These uses are independent of each other and can be combined.

    packres.exe merges the input files into a single file and adds some additional information.

    For example, if we download some prompt tones to the external flash, packres.exe is used twice in total

    First time: packres.exe -n tone -o tone.cfg 1.mp3 2.mp3 ... # generates the prompt tone file

    Second time (the one described in this document): packres.exe -n test_dir -o res.bin tone.cfg # packs the files for download to the external flash

    Do not skip the later step just because packres.exe was already used in the prompt tone step.

  2. In download.c, remove the parameter: -wflash XXXX
    and add the parameter: -ex_flash res.bin

    Note

    Parameters:

    • -ex_flash # parsing parameter required by the 1-to-8 programmer

    • res.bin # the packed resource file; use this name whenever possible, because OTA upgrade recognizes only this name

  3. Add parameters under [SYS_CFG_PARAM] in isd_config.ini, for example:

    Configuration method 1: EX_FLASH=PA08_1C_NULL;

    Note

    Configuration method 1:
    the method used to configure external FLASH in early AC695X SDKs and some AC696X SDKs
    In this example, the CS pin is PA08
    SPI1 port C is used
    If the norflash is powered from vddio, enter NULL; otherwise, enter the corresponding pin number

    Configuration method 2:
    EX_FLASH=PA03_1C_PC01;
    EX_FLASH_IO=4_PC06_PB07_PB08_PB09_PB10;(for 4-wire)
    EX_FLASH_IO=2_PC06_PB07_PB08_NULL_NULL;(for 2-wire)
    EX_FLASH_IO=0_PC06_PB07_PB07_NULL_NULL;(for single-wire half-duplex)

    Note

    Configuration method 2:
    used by some AC696X SDKs and by later models such as AC701N, JL701N, AC707N and AD17N.
    Meaning of the EX_FLASH fields: CS_SPI1/C port_FLASH power pin
    Meaning of the EX_FLASH_IO fields: width_CLK_DO_DI_D2_D3

  4. After modifying and saving, build the project to get a fw that includes the external flash resources, and then authorize it
