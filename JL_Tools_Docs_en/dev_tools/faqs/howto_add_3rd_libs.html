7.3. How to Add a Third-Party Library to an SDK Project

Note

This page was missing from the saved files and was restored from an Internet Archive snapshot (2026-08-24); it may differ slightly from the current online version.

7.3.1. Files included in a third-party library

In some cases, you need to add library files (.a files) provided by a third party. Generally, two kinds of files need to be added:

  1. Header (.h) files. These files generally contain the corresponding function declarations (that is, the declarations of the functions that the .a file provides)

  2. The .a file itself, which contains the implementations of the function bodies

7.3.2. What to check before adding a third-party library

Before adding a third-party library, check the following:

  1. Make sure that the compiler flags of the third-party library are the same as those of the current SDK, because different SDKs may use different instruction sets. First of all, make sure that the compiler flags of the third-party library and the SDK are the same (especially the -target xxx and -mcpu=xx options).

Note

If you are the author of a third-party library and want to package the library yourself, see How to Get a Library Project from an Existing Standard SDK Project

  1. Determine whether the SDK you are using is a Code::Blocks project, a Makefile project or a VSCode project. Different kinds of projects need to be changed in different places.

7.3.3. What to change to add a third-party library

Adding a third-party library mainly involves the following changes:

  1. Copy the .a library file to the SDK project directory, for example to the include_lib\liba\${CPU}\ directory. ${CPU} stands for the CPU model, for example br23. For details, refer to the corresponding directory in the SDK.

  2. Copy the .h header file to the SDK project directory, for example to the include_lib\liba\3rd\ directory. If the directory does not exist, create it yourself.

  3. Modify the linker flags to add the path of the .a library file.
