2.2. Building with make

Newer SDKs support building with make by default (on both Windows and Linux).

There is a Makefile in the SDK root directory. In addition, to support using make on Windows, the SDK comes with an extra tools directory that contains the necessary build tools.

2.2.1. Building with make on Windows

Building on Windows takes two steps. The AC695N SDK is used as an example below:

  1. Open the make_prompt.bat script in the tools directory of the SDK, as shown below:

Note

If there is no make_prompt.bat file in the tools directory, open the make_prompt.bat in the SDK root directory instead. If you still cannot find it, see How to Convert a Code::Blocks Project to a make/VSCode Project.

If you do not use the make_prompt.bat we provide to set the %PATH% environment variable, you need to set it yourself based on the contents of make_prompt.bat.

  1. In the command-line window that opens, type make and press Enter.

2.2.2. Building with make on Linux

Building on Linux takes the following four steps:

  1. First, click to download the Linux toolchain.

  2. Extract the toolchain to the /opt/jieli directory and make sure that /opt/jieli/common/bin/clang exists (pay attention to the directory levels)

  3. Make sure the result of ulimit -n is large enough (greater than 8096 is recommended). Otherwise, linking may fail because many files are opened. You can set a larger value with ulimit -n 8096.

  4. Go to the SDK root directory and type make to build

2.2.3. Steps to troubleshoot Makefile build errors

  1. Check whether the SDK path contains spaces or Chinese characters.

  2. Check whether the SDK path is nested too deeply.

  3. Check whether the tools folder in the SDK root directory matches the tools folder in the conversion tool (click here to download), and check for missing files.

  4. Check whether the corresponding Code::Blocks project can be built, to find out whether there is a problem with the toolchain environment.

  5. If you do not build with the make_prompt.bat we provide, make sure that the %PATH% environment variable is set correctly, that is, that the corresponding toolchain can be found through this environment variable.
