2.5. PC-Side Programming Options for Each Chip Model

Note

If you want these checkbox options to be fixed in the FW/UFW file so that you do not have to select them again for every deployment, see How to Set Programming Options When Generating a Programming File

2.5.1. Opening and selecting configuration items

Before you update the target chip programming firmware, the PC tool's update control panel offers many options that can or must be configured. Normally the defaults are fine, but you can also choose settings according to your needs.

For example, see the relevant steps in the "Update the target chip firmware on the programmer" section.

Open the control panel (version V3.0.3 2) for updating the AC897N chip firmware

The options you can see are Board-change interval (换板时间), Port current upper limit (端口电流允许上限), USB port voltage (USB端口电压), Erase the entire FLASH before programming (烧录前擦除整个FLASH), Calibration query (校准查询), RX current test (RX电流测试), DAC, LVD voltage (LVD电压), LgHg, Bluetooth configuration (蓝牙配置) and Current test items (电流测试项).

This is shown in Chip programming configuration window.

After loading the target chip fw file, configure each option, then click "Deploy" (部署) to update the programmer with the target chip firmware and the configuration information.

Important

The configuration window may differ between programmer firmware versions. Keep the programmer firmware updated to the latest version.

2.5.2. Common configuration items for each chip model

The programming options of different chip models are basically the same; an option with the same name has the same actual function on different chips.

The following table describes some common options for each chip series; configure them as actually needed when programming.

No.

Configuration item

Configuration Items

1

Board-change interval (换板时间)

Default: 1000mS. The time from when a successfully programmed device on the current channel disconnects until programming can start again; the channel cannot program within this time;
Purpose: in mass production, when some device chips fail and are programmed a second time, this reduces repeated programming of device chips that have already been programmed successfully

2

Port current upper limit (端口电流允许上限)

Range: 0~300mA, default: 100mA;
Purpose: if the current drawn by a device plugged into a USB programming port of the programmer exceeds the set value, the programmer software turns off the power of the USB port to protect the programmer's hardware circuits

3

USB port voltage (USB端口电压)

Range: 3.2V~6.3V;
Purpose: set it to the programming voltage required by the device chip

4

Erase the entire FLASH before programming (internal FLASH) (烧录前擦除整个FLASH（内置FLASH）)

Checked by default. Checked: the FLASH is erased whether the chip is blank or non-blank (already programmed);
Unchecked: the FLASH is not erased if the chip is blank. This option controls whether the chip FLASH is erased

5

Calibration query (校准查询)

Checked by default;
Checked: during programming, the chip's ADC reference source calibration parameters are queried;
if the chip has not been calibrated, an error is reported and programming cannot continue, so that actual use is not affected;

6

RX current test (RX电流测试)

Checked: a Bluetooth receive performance test is performed to screen out chips whose Bluetooth receive parameters do not meet the requirements

7

DAC

Checked: an audio DAC module performance test is performed to screen out chips whose DAC parameters do not meet the requirements;
DAC has related parameter settings; the defaults are usually fine

8

LVD voltage (LVD电压)

Sets the chip's low-voltage reset voltage. When reprogramming, set the same value, otherwise an error is reported and programming cannot continue. Choose the LVD voltage according to your actual design and the SDK documentation

9

LgHg

The default parameters are fine. A Bluetooth performance test is performed, and an error is reported if a measured parameter is below the set value; used to screen out chips whose Bluetooth performance does not meet the requirements

10

Bluetooth configuration (蓝牙配置)

Update Bluetooth address (更新蓝牙地址): check it and enter the Bluetooth address range; when chips are programmed, the Bluetooth addresses in the set range are programmed into the chips one by one in ascending order, starting from the lowest address;
Overwrite Bluetooth address (覆盖蓝牙地址):
Checked: if a Bluetooth address has already been programmed into the chip, it is overwritten and a new Bluetooth address is programmed into the chip.
Unchecked: if the chip already has a Bluetooth address, the existing address is used, to avoid wasting Bluetooth addresses when reprogramming;
Update Bluetooth name (更新蓝牙名字): in SDK development, the Bluetooth address can be appended to the Bluetooth name in a specified format to auto-increment the Bluetooth name;
see the "Bluetooth Address and Name Auto-Increment" section;

11

Current test items (电流测试项)

Current tests at power-up, startup, standby and power-off can be performed: set the normal current range to screen out chips whose current does not meet the requirements during programming;
see the "Current and Power Consumption Test" section;

12

SFC verification (SFC校验)

Select the speaker solution or another solution according to your design;
during programming, the firmware data is verified in SFC mode under the voltage test conditions of the selected solution,
to screen out chips that fail the firmware data verification

13

Crystal-less solution (LRC_TRIM) (免晶振方案)

If checked, performs LRC clock calibration on chips that do not need an external crystal, so that the chip's LRC clock source is used as the system clock

14

USB/ISP

Checked: the firmware is programmed in ISP mode, which solves the problem of the programmer not detecting or recognizing an inserted device during programming

15

IQ_TRIM

Checked: Bluetooth calibration parameters are tested

16

Battery type (电池方案)

Sets the chip's LVD (low-voltage reset) voltage according to the operating voltage of the battery type used by the chip;
Options:
Lithium battery (3.0V~4.4V): LVD voltage 2.3V;
Two dry cells (1.8V~3.2V): LVD low-voltage reset disabled;
Coin cell (2.2V~3.6V): LVD voltage 1.8V;
(The configured value is programmed into OTP, which can be programmed only once: after programming with one option, you cannot program again with another option, so choose carefully)

17

Device with battery attached (样机带电池)

Checked: finished devices with a battery already soldered on can be programmed; see the "Programming Devices with Batteries Attached" section;

18

LOOPBACK

If checked, tests Bluetooth performance parameters to screen out chips whose parameters do not meet the requirements

19

Short-press reset (短按复位功能)

Checked: the corresponding configuration value is programmed into the chip to enable the short-press reset function of the corresponding pin;
This option can be programmed only once, so choose carefully

20

Long-press reset (长按复位功能)

Checked: the corresponding configuration value is programmed into the chip to enable the long-press reset function of the corresponding pin;
This option can be programmed only once, so choose carefully

21

Force authentication code update (强制更新认证码)

Checked: when a non-blank chip is programmed, any authentication code already programmed into the chip is overwritten and a new authentication code is programmed;
usually left unchecked (default), so that if the chip already has an authentication code, the existing one is used and no authentication codes are wasted;
see the "Programming Third-Party Data (Authentication Codes)" section;

22

Frequency offset test (频偏测试)

Checked: together with a test box, frequency offset calibration is performed after the device chip firmware is programmed, which removes the separate frequency offset calibration step for devices and improves production efficiency;
see the "Frequency Offset Calibration" section;

23

BTPLL

Checked: BTPLL clock parameters are tested to screen out chips whose parameters do not meet the requirements

24

Bare chip programming (裸片烧录)

Checked: for programming chips that are encapsulated directly with black epoxy and already mounted on the board; the LVD and VDDIO voltage levels of such chips are different;
This option can be programmed only once, so choose carefully

25

DACVDD

Checked: used to screen out chips with an abnormal DACVDD that produce noise

26

LNA_BIAS

If checked, tests Bluetooth calibration parameters to screen out chips whose Bluetooth parameters do not meet the requirements

27

USB screening mode (USB筛选模式)

Normal programming and strict screening modes are available. For AC695X designs, choose the mode depending on whether the design uses the USB pins, to screen out chips with faulty USB pins

28

Full RAM test (RAM全面测试)

Checked: thoroughly screens out chips whose RAM does not work properly

29

MIC test options (MIC测试选项)

There are many settings; see the "MIC Test" section;

30

Erase VM (擦除VM)

This option can be selected only when the full-chip erase option is unchecked;
Checked: the VM area is erased
Unchecked: the VM area is preserved

31

UMDC

Bluetooth-related test item, checked by default

32

Release IO latch (释放IO锁存)

Checked: the IO states are unlocked during an upgrade with the battery attached, and all chip IOs are reset to the high-impedance state

33

Erase the entire external FLASH (擦除整个外置FLASH)

This option is unchecked by default;
it is mainly used when the design of the chip to be programmed includes both internal FLASH and external FLASH, to control whether the entire external FLASH is erased directly;
Case 1: if this option is unchecked, the programmer checks whether the FLASH is blank and, if it is not, erases an area matching the actual size of the firmware data
(because the whole FLASH chip has to be checked for blankness, and some FLASH erases faster than it reads, a full-chip
erase is sometimes faster than a partial erase, so decide whether to check this option according to your situation).
Case 2: if this option is checked, the programmer does not check whether the FLASH is blank and erases the entire FLASH directly before programming.
Case 3: if the chip used in the design has no internal FLASH, only external FLASH, that FLASH is treated as internal FLASH, and its erase behavior is controlled by the [Erase the entire FLASH before programming (internal FLASH)] (烧录前擦除整个FLASH（内置FLASH）) option.

34

Disable HD1 (ports 1-8) (关闭HD1)

This option only affects the IO state of the 8 USB programming ports of the 1-to-8 programmer. It is mainly for some fixture setups: if, with the devices placed on the fixture
and programmed with the 1-to-8 programmer, a device is not recognized for programming or the last programming stage fails with a timeout, and the communication wiring between the 1-to-8 programmer and the devices has been checked and is fine,
try checking this option to see whether it solves the problem. Normally this option does not need to be checked

35

Flash LVD voltage match (Flash Lvd电压匹配)

Checked: checks whether the minimum operating voltage supported by the chip's Flash matches the selected lvd voltage;
(1) if the selected lvd voltage is greater than or equal to the minimum operating voltage supported by the Flash, programming is allowed;
(2) otherwise, programming is not allowed, and the programmer reports an error showing the minimum operating voltage of the chip's flash;
(3) if this error is reported, uncheck the option and select the lvd voltage level you need; it is generally recommended to program with the highest lvd voltage level

36

Reference source (参考源)

This option takes effect only when Crystal-less solution (LRC_TRIM) (免晶振方案) is checked. If some devices are not recognized for programming or communication fails, you can try unchecking this option and programming again;
whether the Reference source (参考源) option is checked or not does not affect the configuration and firmware data programmed into the chip

37

Program external Flash? (是否烧录外部Flash)

When the programming file contains, in addition to the internal FLASH firmware, external FLASH data and the external FLASH IO configuration, or only the external FLASH IO configuration, the deployment window
shows Program external Flash? (是否烧录外部Flash). It is checked by default and the external FLASH is programmed. When it is unchecked, the external FLASH data is not deployed to the programmer, so the external FLASH data is not programmed either;
only the internal FLASH is programmed. If, apart from the internal FLASH firmware, the programming file contains only the IO configuration for the external FLASH, Program external Flash? (是否烧录外部Flash) generally must be unchecked

38

Charging enable (充电使能)

This option controls the VBAT output in the initial power-up phase of the chip and is checked by default. Some designs connect VBAT and VDDIO together,
so the VBAT voltage output in the initial power-up phase may need to be turned off; in that case you may need to uncheck this option for programming. Configure it according to your actual application

39

USB_VCC

This option is grayed out (inactive) by default. It has two drop-down choices, ON and OFF, and becomes available only when [Device with battery attached] (样机带电池) or [USB-device with battery attached] (USB-样机带电池) is checked.
It sets whether the power of the programmer's programming ports is on or off during an upgrade with the battery attached; set it on or off according to the actual situation. If the upgrade with the battery attached
has to be triggered through the USB power pin, set it to on. Some devices have many components or large capacitors and draw a large current, so it should not be on; in that case
you can set it to off or leave the power wire of the programming port unconnected to the device.

40

MAC/authentication code (EFUSE) (MAC/认证码)

This option writes the authentication code or MAC address to EFUSE. It is generally used in FLASH designs: when the FLASH capacity is insufficient, you can choose to program the MAC address or the
authentication code into EFUSE to keep FLASH space free for the application.

41

Skip calibration items (跳过校准项)

On some chip models, the frequency offset calibration value or data such as the Bluetooth name is stored in efuse. If, after a FW file is first programmed, you perform frequency offset calibration with a Bluetooth test box or
change the Bluetooth name, and then reprogram with the original FW, programming fails. In that case, select [Skip calibration items] (跳过校准项) for programming.

42

LRC_TRIM (AD15N model)

If the device has no battery attached and the programmer controls power on/off for programming, with LRC=-1 configured in isd_config.ini and the [LRC_TRIM] option checked, the LRC is
recalibrated and written to flash. If programming with the battery attached is checked, with LRC=-1 configured in the fw file's isd_config.ini and the [LRC_TRIM] option checked, the LRC is not
recalibrated; the programmer only checks whether there is a calibration value in flash and, if there is, reads it back and writes it to flash again when the firmware is reprogrammed,
that is, the original LRC calibration value in flash is preserved.

2.5.3. Programming MAC addresses and authentication codes

2.5.3.1. Important options

  • Overwrite Bluetooth address (覆盖蓝牙地址): when checked, each successful programming of a device consumes one MAC address.

  • Force update authentication code (强制更新认证码): when checked, each successful programming of a device consumes one authentication code.

Core principle: as long as you make sure that each device is ultimately programmed successfully only once, the number of MAC addresses (or authentication codes) consumed corresponds exactly, one to one, to the number of successfully programmed devices. Programming failures do not affect the count: no matter how many times a device
has failed before, it consumes only one MAC address or authentication code once it is finally programmed successfully.

2.5.3.2. Normal programming scenario (programming with a fixture)

When programming with a fixture, the same board may be reprogrammed repeatedly, so to avoid consuming MAC addresses and authentication codes repeatedly, usually do not check [Overwrite Bluetooth address] (覆盖蓝牙地址) and [Force update authentication code] (强制更新认证码).

When programming MAC addresses or authentication codes with the 1-to-8 programmer, make sure that the number of successfully programmed devices corresponds exactly, one to one, to the number of MAC addresses (or authentication codes) consumed. Use programmer version 3.1.33
or later. The key points are as follows:

  1. Successfully programmed devices: because [Overwrite Bluetooth address] (覆盖蓝牙地址) and [Force update authentication code] (强制更新认证码) are unchecked, programming them successfully again does not consume new MAC addresses or authentication codes.

  2. Devices that fail programming: a device that still fails after several attempts must be marked immediately and removed from the current programmer. Do not leave it on the current programmer for further attempts, and do not plug it into another channel at random for programming,
    otherwise the number of devices will no longer match the number of MAC addresses/authentication codes.

2.5.3.3. Handling failed devices

Devices that failed programming should be collected and handled separately in one of the following ways:

  • Redeploy the firmware (FW) to a new programmer and then program them;

  • Or handle them with a programmer that has completed the count for this batch.

When handling them, check the option that corresponds to what is being programmed:

  • Programming MAC addresses → check [Overwrite Bluetooth address] (覆盖蓝牙地址)

  • Programming authentication codes → check [Force update authentication code] (强制更新认证码)

For each device, make sure it is programmed successfully only once; do not program it a second time after it has been programmed successfully.
